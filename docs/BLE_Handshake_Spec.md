# Hadeed BLE security baseline

هذه الوثيقة لا تعتمد XOR ولا مفاتيح ثابتة داخل التطبيق. قيمة `0x5F` و`0x55AA`
القديمة كانت placeholders وليست حماية تشفيرية، ولا يجوز استخدامها في منتج.

## المتطلبات قبل الإنتاج

1. استخدام Secure Connections في BLE عند توفره.
2. استخدام challenge عشوائي من الجهاز مع توثيق قائم على مفتاح سري مُدار خارج
   التطبيق، وليس سرًا ثابتًا داخل APK.
3. استخدام AEAD قياسي مثل AES-GCM أو ChaCha20-Poly1305 للبيانات التي تحتاج
   سرية، مع nonce فريد لكل رسالة.
4. رفض replay عبر sequence وnonce ونافذة زمنية.
5. تدوير المفاتيح وإبطال الجهاز عند فقدانه.

## حالة التنفيذ

مصادقة BLE الإنتاجية **غير مكتملة بعد**. إلى أن يتم اعتماد مخطط provisioning
وتخزين المفاتيح في hardware-backed keystore، يجب اعتبار قناة التطبيق غير
موثوقة وعدم إرسال بيانات حساسة أو ملفات firmware عبرها.

صيغة الإطارات غير الأمنية موثقة في [Protocol V1](../protocol/README.md).
